# Pi native Worker

W1 ordinary Worker implemented in TypeScript, tested on Windows x64 with Node 24.16.0 and macOS arm64 with Node 24.22.1 and the exact Pi SDK 1.4.0 npm tarball. A managed child calls `createAgentSession()` directly. It does not use the Pi CLI, CLI RPC, a JVM, or the user's installed Pi/profile. `package-lock.json` and `UPSTREAM.lock.json` pin the build inputs; upstream packages retain their MIT licenses.

The host binds only `127.0.0.1`, requires a 24+ character owner bearer token, rejects browser Origins, and supports the existing `/local/v1` consumer plus `/worker-host/v1/manifest`, `/capabilities`, and read-only `/operations/lookup`. The optional `X-Worker-Local-Store` header fences stale store references. API clients retain the original request key and query it after an uncertain response.

`engineBindingDigest` (also exposed as the compatibility `executableDigest`) hashes the actual Node executable bytes, installed Pi package manifest and all `dist/*.js` bytes, compiled Worker JS and npm lock. Manifest provenance identifies this explicit coverage and selected file hashes. The startup binding is frozen and rechecked before native prompting; a changed binding rejects dispatch. This is a byte fingerprint of the listed inputs, not complete installed transitive dependency attestation. The latter remains a release qualification gap.

## Build and launch

```powershell
cd pi
npm ci
npm test
# MODEL_API_KEY, MODEL_DEFAULT_MODEL, MODEL_BASE_URL and WORKER_LOCAL_TOKEN
# must already be set in the environment. No secret files are created here.
node dist/host/main.js init --state .local/pi-host --project D:\your\git-project --project-id project
node dist/host/main.js serve --state .local/pi-host --port 18731
```

`init` registers an existing Git root with a committed baseline. The working copy is cloned from that baseline, preserving uncommitted source changes in the original repository. An execution occupies a slot until its turn settles or execution ends. A completed live task keeps its session for follow-up, which needs an available slot. STOP can prove quiescence for artifact sealing. A proven completed and sealed session also accepts an explicit new follow-up after STOP/restart. Each task has its own clone, native session directory, isolated in-memory settings/provider, and managed resource tree. HOST is not an OS sandbox: the model's shell runs under the host OS identity. Unreviewed user/project extensions and automatic resource discovery are disabled.

An existing project alias cannot be rebound to a different real directory within the same store. Missing model name, endpoint, API key or required Zen session header reports execution UNCONFIGURED and prevents new execution; persisted reads and STOP remain available.

Both explicit model name and base URL are required; no production model is selected implicitly. API keys and `LLM_HEADER_*` values are captured only in the child model runtime, then removed from the shell environment. No owner token or unrelated credential is forwarded. The header variable suffix maps underscores to hyphens, for example `LLM_HEADER_x_opencode_session` supplies the required Zen session header. Only header environment **names** are stored in the task binding. Model context/max-token values are compatibility assumptions, recorded as such; actual emitted token usage is separate from unknown monetary cost.

## Durable behavior

`ledger.sqlite` uses WAL and FULL synchronous commits for installation identity, original requests, task facts, input questions, finalized public messages, event sequences and immutable artifact bytes. An independent SQLite EXCLUSIVE transaction in `owner.sqlite` prevents two hosts from owning the same state directory. In-place restart preserves authority/store/worker identity and changes boot identity. Copying state to a new installation is not supported by this slice.

Acceptance and `DISPATCHING` are durable before native prompting. Repeating an identical key returns its original receipt even after restart; changing body/guard or crossing task scope rejects it. A host crash in `DISPATCHING` becomes UNKNOWN and never silently reissues the prompt. Interrupted turns from an earlier host boot keep their recorded outcome uncertainty and relinquish execution capacity. Event pages have durable decimal-string cursors; output exposes finalized public text only, with bounded output and unknown cost. No private reasoning is exported.

Each Windows task process and Git preparation process starts behind an input gate. The host assigns it to an owned Windows Job before sending any execution configuration. The Job disallows breakaway and has KILL_ON_JOB_CLOSE. STOP closes intake first, uses the retained Job handle, and reports APPLIED/quiescent only after `QueryInformationJobObject` returns zero active processes. The same proof covers a real descendant heartbeat writer in tests. STOP is also accepted before a native session exists and cannot be revived by late preparation. Closing/killing the host closes its Job handles. Remote side effects performed before STOP are not undone.

On macOS arm64, the input gate stays closed until an independent Node guardian registers Darwin `EVFILT_PROC` / `NOTE_FORK | NOTE_EXIT` against the native process. The guardian inherits only its host IPC lifetime lease, not model credentials. STOP or host IPC loss kills the original live process group; native bootstrap stays alive until guardian teardown so host death does not first orphan its tools. A proof is accepted only when no fork was observed, the kernel observed the root exit, and the group is absent: `DARWIN_KQUEUE_NO_FORK_GROUP_ZERO`. Built-in `read`/`write`/`edit`/`ask_user` tasks can therefore STOP, seal artifacts, and reopen the persisted completed session. The compiled guardian is included in the existing Worker JS byte fingerprint; no additional dependency or runtime compiler is required. Git preparation also starts gated under a guardian with fixed local clone/checkout commands and credentials removed.

Any observed fork permanently vetoes the macOS whole-tree proof, including an ordinary successful `bash` call whose children have already exited. The guardian still cleans up the original group, but STOP returns `UNKNOWN`, `quiescent` stays false, artifacts and completed-session reopen stay unavailable. A settled turn keeps its recorded result and frees the execution slot. A real `detached: true` (setsid) writer in tests survives group cleanup and is then explicitly killed by its owning test. Darwin does not support `NOTE_TRACK`; group emptiness cannot certify escaped descendants. Guardian observation loss, early root exit with uncertain descendants, and host crash without a durably recorded proof also remain UNKNOWN. An orderly proven close of a PAUSED task preserves resume; an abrupt host kill while PAUSED requires reconciliation and does not advertise resume. macOS support is therefore PARTIAL and does not claim arbitrary shell tree containment or an OS sandbox. Windows retains its Job ownership path. Linux remains unqualified.

For a bounded macOS file-tool path, explicitly select `--execution-profile macos-in-process-v1` on **both** `init` and `serve`. The wire `profileId` remains `MANAGED`; the separate versioned `executionProfile` is exposed in the manifest/preflight and bound into task, checkpoint and engine digests. This profile launches the gated Node engine through `/usr/bin/sandbox-exec` with a fixed allow-default / deny-`process-fork` policy, and exposes exactly `read`, `write`, `edit`, and `ask_user`. Bash and process-based search tools are absent. A denied spawn is tested as actual EPERM; the guardian still independently requires its no-fork/exit/group-zero proof before sealing results. This policy bounds process creation only: filesystem and network access remain under HOST identity and the existing write-scope gate. Sandbox wrapper bytes and policy hash are fingerprinted. Fixed Git preparation remains outside the no-fork engine profile.

For real shell/build/test on macOS, explicitly select `--execution-profile macos-runner-v1` on both `init` and `serve`, using a fresh state directory. This keeps the model runtime under the same deny-process-fork policy and adds custom `bash`, `run_command`, `run_build`, and `run_tests` tools alongside `read`/`write`/`edit`/`ask_user`. The custom `bash` replaces the SDK shell implementation: all four command tools send IPC to the host, which submits authenticated loopback HTTP to the fixed shared `workers/command-runner/main.mjs` snapshot using the host's physical Node executable. The engine binding includes Node plus the Runner's sorted `guardian.mjs`, `main.mjs`, and `runner.mjs` bytes. The wire `profileId` remains `MANAGED`, and the real model ID remains unchanged.

Each task/segment binding owns a separate Runner state directory, dynamic loopback port, random memory-only token and stdin owner lease. Context and original command key bind task, generation, segment, native session/turn, current user command, execution profile and engine digest. Only base toolchain variables plus explicitly declared non-secret task environment names reach the Runner; model credentials and control tokens never reach commands. Command cwd must remain inside the task clone. This does not statically restrict shell file writes or make HOST an OS sandbox.

Runner receipts are durable in task detail and audit. They distinguish stdout/stderr, process exit code, build command success, and test evidence. `run_tests` grants `nonzeroExecuted`/`passedWithTests` only from a single complete Node TAP summary with observed test/pass/fail counts; exit zero with no recognized test report stays test qualification `UNKNOWN`. Other test frameworks remain usable as commands but need their own report interpretation. An explicit pre-dispatch HTTP rejection such as outside-workspace cwd becomes a tool error without claiming an uncertain execution. An uncertain submission is queried only by its original key, never automatically resent; unknown settlement closes task intake and prevents sealing/reopen.

STOP closes every context created by the task before stopping its model runtime. It requires each context closed with empty active/unknown command lists and the independent model no-fork guardian proof. Its method is `MODEL_NO_FORK_AND_REGISTERED_PROCESS_GROUP_ZERO`, with scope `MODEL_NO_FORK_AND_REGISTERED_PROCESS_GROUPS` and `arbitraryEscapedProcesses: NOT_PROVEN`. Ordinary command forks/pipelines work and can settle successfully. Observed detach, lost ownership or crash uncertainty remains `UNKNOWN`; this is registered process-group cleanup, not arbitrary escaped-process containment. Host death closes the stdin lease, the Runner cleans owned groups and records uncertainty, and restart preserves original receipts without replay. The original `native` and file-only profile keep their existing behavior.

`npm run test:model:runner` runs the real selected model through command output/nonzero exit, a small npm build, a failing real test followed by model file repair and a passing nonzero test suite, STOP, persisted session/command receipts, a long-command heartbeat STOP, and external host SIGKILL plus original-key recovery without replay. `test/runner.test.mjs` runs the same SDK/IPC/HTTP/process boundaries against a local scripted model, including credential absence, immutable binding and pre-dispatch cwd rejection. Sanitized real-model evidence is in `test/evidence/macos-arm64-runner-deepseek.json`. The final macOS deterministic suite has 43 tests (41 PASS, 2 Windows-only SKIP); shared Runner lifecycle tests have a separate entry point under `workers/command-runner/test/`.

Execution profile is an immutable store binding: initialize a fresh state directory for the new profile. Stores initialized as `native` (including legacy stores without an explicit profile marker), `macos-in-process-v1`, or `macos-runner-v1` cannot be opened under a different execution profile; startup rejects `EXECUTION_PROFILE_CHANGED` without silently migrating tasks. The default direct host profile remains `native`, retaining its shell/UNKNOWN behavior and prior evidence. To repeat the bounded real-model smoke after approved environment loading, run `node test/model-smoke.mjs macos-in-process-v1`.

Pi has no public native turn identifier; `nativeTurnId` is null and each explicit prompt has a separate logical `segmentId`. Mutations bind the exact generation/session/current command; missing Pi turn and null are equivalent. Managed `ask_user` questions support confirm/select/input, original binding and one answer. Direct prompt consumption is correlated by its invocation; queued steer reports ACKNOWLEDGED without claiming consumed from matching text. Real smoke verifies the resulting steer file separately.

## W4a: budgets, write scope, environment binding, audit/diagnostics, queue

Task creation accepts three optional declarations. `budget` requires `enforcement: 'SOFT'` — usage arrives post-hoc from SDK-reported assistant events and accumulates into a per-response `usageLedger` (source `ENGINE_REPORTED`, bounded to the most recent 256 records; `ESTIMATED`/`UNKNOWN` remain valid ledger vocabulary and cost stays `UNKNOWN`, never zero), so hard provider-side caps are unavailable and rejected. Positive-integer caps (`maxTotalTokens`, `maxInputTokens`, `maxOutputTokens`, plus `maxCostMicroUsd` recorded but unevaluated while cost coverage is unknown) are checked inside the same awaited `before_provider_request`/`tool_call` gate used by PAUSE, before the request or tool is dispatched. Exceeding a cap makes the run terminal `BUDGET_EXCEEDED` with a `budget.exceeded` event carrying actual counters; the child is released through the qualified platform teardown, receipts/history/artifacts stay readable, STOP is still accepted and does not erase the verdict. Follow-up input is refused with `BUDGET_EXCEEDED` until a guarded `EXTEND_BUDGET` command supplies strictly larger caps, which reopens the sealed session file and continues as a new segment (same native session, `resumeVia: SESSION_REOPEN`). A host crash between the exceed decision and the durable write reconciles UNKNOWN; `BUDGET_EXCEEDED` survives restart and can still be extended.

`writeScope: { extraWriteDirs?, denyPaths? }` is an explicit policy. File-mutating tool calls (`write`/`edit`/patch-family path args) are resolved (relative to the workspace; `..`, Windows case-insensitive drive paths; POSIX separators and real paths on macOS, best-effort realpath for symlink escapes) inside the awaited `tool_call` gate and denied with a real tool error plus a `write.scope.violation` event — unlike the W3 hold, the run stays alive. Shell-command paths are not statically attributed and remain a documented gap. The scope binding is persisted in the task row and each checkpoint manifest.

`environment: { requiresCommands?, requiresDirs?, envAllowlist? }` is bound at PREPARING admission and re-validated on every relaunch: commands must resolve on the host `PATH` and directories must exist readable — any miss is terminal `BINDING_UNAVAILABLE` with reason detail, no host-env fallback and no child. `envAllowlist` names (`^[A-Z][A-Z0-9_]{0,63}$`, secret-pattern names and `LLM_`/`MODEL_`/`WORKER_`/`ACS_`/`PAC_` prefixes rejected) copy present host values into the child env for toolchains such as `JAVA_HOME`, never credentials.

`GET /worker-host/v1/tasks/{taskId}/audit` returns ordered durable facts: subject request key, every command receipt, dispatch marks, native turn ids, effect transitions, artifact writes and state transitions — no prompt bodies. `GET .../diagnostics?redact=content` replaces message/tool bodies with `{sha256,size}` refs and scrubs secrets and absolute host paths from every included string; full bodies remain available through the normal event/artifact reads.

Admission is slotted: `NWF_PI_MAX_ACTIVE_TASKS` (default 4, min 1) concurrent task executions, including preparation and dispatch. Beyond the cap a create is still accepted idempotently but lands `launchState: QUEUED` with a durable ordinal and is admitted strictly in create order as execution slots become available; task detail exposes `queue.position`. A QUEUED intent was never dispatched, so a restart re-evaluates and dispatches it exactly once through the same request/generation machinery. Paused in-flight turns retain their slot until they settle or execution ends. The execution deadline does not stop a settled or paused turn.

An explicit `NATIVE_FOLLOW_UP` can reopen a completed session only when SUCCEEDED, native idle, all questions settled, and an OS-qualified quiescence proof has sealed the exact native session bytes. Reopen verifies that seal, the SDK/model binding and owned workspace before accepting a new command. `SessionManager.open()` remains the context authority; the new generation/segment preserves the native session ID and previous receipts. This never retries an interrupted/unknown prompt and does not set `continueAfterRestart`. Modified session bytes are rejected. Tests verify actual prior messages reach the next SDK model request and the selected real model recalls the earlier user answer after restart.

Artifacts are available after proven STOP and are sealed against the frozen baseline, including untracked, modified and deleted files. Traversal, symlink, oversized, changed-during-read and detected-secret entries are withheld. Bytes and manifest publish in one SQLite transaction. Clients use opaque IDs and base64 sealed bytes; digest is checked on each read. New segments produce new artifact IDs while previous published refs retain their original bytes. No client path is accepted as a download source.

## W4b: task terminals, MCP servers, skills and extensions

`POST /local/v1/tasks/{taskId}/terminals` accepts `{argv:[...]}` and spawns a **pipe session** — never a PTY — with `cwd` equal to the task workspace and piped stdio. Each terminal is assigned to its own owned Windows Job on creation (process group on POSIX), so the tree cannot escape ownership. Input is base64 bytes via `.../terminals/{id}/input` (16 KiB per write); output is a bounded 256 KiB ring read through `.../output?cursor=&maxBytes=&waitMs=` where the cursor is the absolute byte offset — an expired cursor returns `truncated: true` instead of fabricating history. `.../signal` accepts TERM/KILL/INT: on Windows, KILL tears down the Job (`taskkill /T` fallback), and TERM/INT request a graceful `taskkill /PID /T` tree exit since no real POSIX signals exist. `DELETE` closes the session. `POST .../resize` returns `NOT_SUPPORTED` — there is no ConPTY implementation, and the engines surface reports `terminals.pty: false` and `resize: false` honestly. Task STOP kills every owned terminal first and records `TERMINALS_STOPPED` with per-terminal `activeProcesses: 0` Job proof; a host crash reconciles persisted live terminals to `LOST`/`HOST_RESTART_JOB_CLOSED`. Terminal lifecycle facts (`TERMINAL_CREATED`/`TERMINAL_INPUT`/`TERMINAL_SIGNAL`/`TERMINAL_EXITED`/`TERMINAL_CLOSED`) are durable and appear in the audit projection; input byte counts are recorded, never content.

Task creation also accepts `mcpServers: [{id, command, args, env?}]`, `skills: [{name, sourcePath}]` and `extensions: [{name, sourcePath}]`. MCP servers are stdio-only; `env` must be literal values — secret-shaped names and `$VAR`/`${VAR}`/`!cmd` indirection are refused (`MCP_ENV_DENIED`) so no host environment or command execution smuggles into the binding. The host injects an inline `createMcpExtension` plus a registrar extension into the child; the SDK connects the servers on `session_start` and the child's tool allowlist names each `mcp__<server>__*` namespace so the tools are actually model-visible. `mcp.bound` records the tools the session itself observed within a bounded wait — a server that never registers tools reports `UNVERIFIED`, never claimed bound. MCP calls flow through the same `tool_call` gate, so writeScope and budget checks apply to them.

Declared skill and extension source directories are copied into the task-managed profile (`sessions/<task>/profile/{skills,extensions}/`) at launch — never loaded in place, never discovered from `~/.pi` or workspace `.pi`. A content SHA-256 over the copied tree is persisted per resource (`skill.bound`/`extension.bound` facts) and re-verified on every relaunch; drift is terminal `RESOURCE_BINDING_CHANGED`, and symlinks, >64-file or >4 MiB trees are refused. Skills load through the real `loadSkillsFromDir` into the system prompt; extensions load through the SDK's real jiti loader (entry discovery mirrors the SDK: `package.json` `pi.extensions` or `index.ts|index.js`) and `session.bindExtensions` emits the real lifecycle with `extension_error` facts for hook failures. Load failures (`extension.load_failed`) and skill diagnostics are durable facts, not silent.

## W5a: context packages, auxiliary sessions, same-engine transitions

`POST /local/v1/tasks/{taskId}/context-packages` accepts `{requestKey, name?, sources:[]}` where each source is `{kind:'file',path}`, `{kind:'text',text}` or `{kind:'summary',text}`. File sources are resolved through the same realpath/junction logic as `writeScope` and must land inside the task workspace — out-of-scope, oversized or missing sources are refused (`PACKAGE_SOURCE_OUT_OF_SCOPE`, `PACKAGE_SOURCE_TOO_LARGE`, `INVALID_PACKAGE_SOURCES`; ≤20 sources, ≤256 KiB per file, ≤1 MiB per package). Bytes are snapshotted at creation, stored immutably, and hashed once into a durable SHA-256 `digest` over canonical source records; `GET .../context-packages` lists metadata and `GET .../context-packages/{id}` returns stored text plus base64 file bytes. Later workspace writes never mutate a package, and `context-package.created` is a durable event.

`POST /local/v1/tasks/{taskId}/auxiliary-sessions` starts **isolated read-only research**: `{requestKey, question, contextPackageIds?, budget?{maxTotalTokens}}` forks a separate engine child with its own native session directory and a materialized read-only workspace snapshot, so auxiliary work can never write the parent workspace and never consumes the parent budget ledger (its own `SOFT` token cap is optional and independent). Selected context packages are injected as fixed instruction material. A bounded pool (≤4 aux children host-wide, ≤4 sessions per task) shares the main host concurrency without displacing task slots. `GET` routes expose `RUNNING|SUCCEEDED|FAILED|CANCELLED`, the question and the answer; `POST .../stop` kills only that aux child; `POST .../deliver` injects the answer into the parent **through the normal follow-up path and all of its guards** — a RUNNING parent refuses with `NATIVE_NOT_IDLE`, and the answer is absent from main output until an explicit deliver. `aux-session.started|completed|delivered` are durable; a running aux reconciles to `CANCELLED` on host close/restart and is never silently resumed. This is not writable collaboration.

`POST /local/v1/tasks/{taskId}/transitions` performs a **same-engine, same-native-session assignment transition**: the current owner epoch is quiesced through the existing PAUSE/STOP machinery, the Pi session is reopened, and a new `ownerEpoch`/`generation`/`segment` admits a continuation prompt. Requests carrying a stale epoch are fenced. A `targetProfile` naming a different engine or an incompatible model/tool set is refused with `INCOMPATIBLE_TRANSITION` and no state change; `transition.quiesced` and `transition.admitted` are durable and `GET .../transitions` lists `transitionId`, `fromEpoch`/`toEpoch`, segments, compatibility method and `createdAt`. Transition from `PAUSED` reopens the sealed checkpoint; transition of a proven completed session reuses the reopen path. **No cross-engine hot migration is supported or claimed.**

`GET /local/v1/engines` now advertises `contextPackages: true`, `auxiliarySessions: true` and `transitions: {sameEngine: true, crossEngine: false}`.

## W5b: writable collaboration DAG and result adoption

`POST /local/v1/tasks/{taskId}/collaborations` accepts `{requestKey, name?, children:[{childId?, goal, dependsOn?, budget?, writeScope?, contextPackageIds?}]}` (≤8 children, `childId` whitelist `[a-z0-9-]{1,64}`, auto `child-N` ids when omitted). Each child is a **writable execution**: a separate engine child launched against an isolated snapshot COPY of the task workspace under `state/collab/<collabId>/<childId>/` (regular files, `.git` and symlinks skipped, bounded like the aux snapshot) with the per-file sha256 baseline sealed at its own spawn — a child waiting on dependencies snapshots the parent tree it actually starts from. `dependsOn` gates scheduling: a child launches only when every dependency reached `SUCCEEDED`; a dependency `FAILED`/`CANCELLED`/`BLOCKED` marks dependents `BLOCKED`/`DEPENDENCY_UNSATISFIED` (partial failure — the collaboration still completes and reports per-state counts). Each child has its own SOFT budget ledger (never the parent ledger) and its file-mutating tools are scope-gated to its own checkout plus any declared `writeScope`. Running children share a bounded host-wide pool (`NWF_PI_MAX_ACTIVE_COLLAB_CHILDREN`, default 4) and ≤4 active collaborations per task; `GET .../collaborations[/{id}]` lists per-child state, baseline/candidate digests, usage and adoption records. `POST .../collaborations/{id}/stop` drains running children with the owned-Job `ActiveProcesses=0` proof, marks pending children `BLOCKED`, and is idempotent; parent `STOP` and host close propagate the same drain (`PARENT_STOP`/`HOST_CLOSE`), while a restart reconciles recorded `RUNNING` children to `CANCELLED`/`HOST_RESTART_JOB_CLOSED` and pending to `BLOCKED` — completed child history and checkouts persist (N19). Children are autonomous: `ask_user` is declined, never routed to the parent. Durable facts: `collaboration.created|child.started|child.completed|child.failed|child.blocked|child.budget_exceeded|child.scope_violation|completed|stopped` — goal bodies stay out of events (sha256 refs only).

`POST .../collaborations/{id}/adoptions` accepts `{requestKey, childId, mode:'ALL'|'FILES', paths?}` and writes a `SUCCEEDED` child's candidate output into the **parent** workspace. The candidate is the diff of the child's isolated checkout against its spawn baseline (added/modified files, plus deletions). Precheck: a path adopts cleanly only when the parent still equals the baseline there — parent drift (`PARENT_DRIFT`), checkout/parent path escapes (`CANDIDATE_ESCAPE`/`PATH_ESCAPE`) and `writeScope.denyPaths` hits (`SCOPE_DENIED`) return a `409` CONFLICT material with the per-file sha256 conflict list and **nothing is written**. A parent path already equal to the candidate is an idempotent no-op, so an empty diff or a repeat adoption records `NO_CHANGES` (same `requestKey` replays the original receipt; a second distinct adoption of identical content is a `NO_CHANGES` fact, never a double-apply). `mode:'FILES'` adopts only the listed candidate paths; deletions remove the parent file only when it still equals baseline. `collaboration.adopted`/`collaboration.adoption.conflict` record file sha256s — never contents (N20). Adoption is file-level, not a git merge; isolation is copy-based with no OS read-only enforcement; AMC/cross-core delegation stays GAP.

## W6: enterprise `/worker/v1` daemon wire (P25)

`src/wire/` adds a TypeScript enterprise adapter that speaks the established `agent-worker/1.4` control-plane protocol while delegating all execution to the embedded local host — the `/local/v1` surface is unchanged and the wire layer never executes work itself. `node dist/wire/main.js --config wire.json` (or `PI_WIRE_CONFIG`) composes `PiHost` + `EnterpriseWireAdapter` in one process; the worker credential arrives through `PI_WORKER_TOKEN` or config, never a file.

Endpoints implemented: `registrations`, `heartbeats`, `commands` long-poll (≤20 s), `commands/{id}/receipt`, `events:batch`, `approval-requests`, `artifacts/upload-intents` + `artifacts/{id}/complete`, `attempts/{id}/finish` + `finish-receipts/{finishId}`, and `recoveries`. A SQLite journal (`wire.sqlite`, WAL + FULL sync) persists the durable boot ID, bound `instanceId`/`streamId`/`workerLeaseEpoch`, a command inbox with original-key replay and stored receipts, an event outbox (schema `1.0`, ≤100 events / 1 MiB per batch, monotonic per-stream sequence), artifact delivery state, and finish declarations that are reposted — identical digest — until a terminal `DELIVERY_ACCEPTED`/`REJECTED` receipt is observed. Receipts carry stable `commandId`/`state`/`revision` and are retransmitted verbatim after a dropped acknowledgement (`detailCode: 'REDELIVERED'` marks resends). Heartbeats (10 s default) carry the bound lease/epoch and backlog counts; lease loss forces re-registration under the same durable boot ID. `DRAINING` rejects new `startTask` honestly while still receipting drain commands; `STOP`/cancel maps to the local `STOP` intent and finishes `CANCELLED`. A restart creates a `/worker/v1/recoveries` session scoped to the prior instance/stream, reconciles stranded attempts through the legal lifecycle ladder (never fabricating success, and treating local `UNKNOWN` as unresolved rather than terminal), and delivers the finish under the recovery session/ticket.

Artifact blobs are delivered through `upload-intents`: intent → PUT bytes → `complete` with the sha256 digest; rows already `UPLOADED` resume at the complete step. R11 credential hygiene holds: cross-origin upload targets receive **no** worker `Authorization` and no `recoverySessionId`/`recoveryTicket` parameters, while same-origin control-plane requests carry the worker bearer. JSON field names, path shapes, `sha256:` digest format and canonical-JSON hashing mirror the Java `agent-worker-protocol`/daemon contract, and project mapping is an explicit config table — no implicit project binding.

The daemon can also front an **external** `/local/v1` host process — the adapter is engine-agnostic and speaks only `/local/v1`; `localEngineId` selects the engine id sent in preflight/create. `host.external = {command, args?, readyPattern?, tokenEnv?, env?, state?, readyTimeoutMillis?}` spawns the child with a generated ≥24-char bearer exported under `tokenEnv` (default `WORKER_LOCAL_TOKEN`), scrapes the first stdout line matching `readyPattern` (default `/LOCAL_TASK_READY (http:\/\/127\.0\.0\.1:\d+)/`) for the bound URL, and runs the adapter unchanged. `host.codex = {hostExecutable, state, executable?, init?, port?, tokenEnv?, env?, readyTimeoutMillis?}` is sugar mapping to `codex-native-worker serve --state <dir> --port <0> --token-env <name>`; `state` must be an initialized state dir (template copy or `init` run — `executable` + `init:{project,projectId,model,baseUrl}` perform a one-time `init` when `registry.json` is absent), and codex mode defaults `localEngineId='codex'`, `capabilities.providers=['codex']`, `executionProfiles=['codex.standard']`. Teardown is honest: `stop()` drains the adapter, then kills the spawned host and awaits its exit; a host dying while the daemon is up resolves `hostExit` and the standalone process exits non-zero — no silent zombie.

External-mode coverage: `test/fixture-local-stub.mjs` (a trivial spawned `/local/v1` responder, not a real engine) proves the spawn/ready-parse/generated-token plumbing through register→startTask→events→artifacts→finish, and that a child crash surfaces on `hostExit` rather than being absorbed.
