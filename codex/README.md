# Codex native Worker (W2+W3+W4a+W4b+W5a+W5b)

Rust loopback host with a SQLite ledger and one managed, isolated Codex app-server per task. It runs without a JVM and preserves the existing `/local/v1` producer/consumer shapes. This covers the W2 closed loop, the W3 durable-recovery prerequisites and stopped-session follow-up, the W4a capability-gated slice (soft budgets, bounded write scope, environment binding, audit/diagnostics and concurrency slots), the W4b slice (task-scoped native terminals, task-bound stdio MCP servers, staged skills/hooks/extensions), the W5a slice (durable frozen context packages, isolated auxiliary research sessions, and same-engine assignment transitions), and the W5b slice: writable collaboration DAGs with guarded explicit adoption. The full NWF P01-P32 fleet is not qualified by this slice.

The tested native dependency is **codex-cli 0.163.0-alpha.11.2 on Windows x86_64 and macOS arm64**. `protocol/codex.lock.json` pins the binary, generated protocol schema and adapter revision. `init` checks the installed executable and its generated schema; each launch rechecks executable/configuration digests. The binary is supplied separately and the user's global Codex installation/home is never changed. Other platforms remain unqualified. macOS qualification uses the explicit `macos-in-process-v1` and `macos-runner-v1` profiles described below; the unrestricted native tool profile cannot prove escaped descendants have stopped.

## Build and start

Use Rust with a working native linker and C compiler (SQLite is bundled). `Cargo.lock` fixes crate versions. The tested Windows build uses Rust **1.99.1 GNU**, LLVM-MinGW **20260908**, and Rust's bundled `rust-lld`. The optional build helper accepts a portable LLVM-MinGW directory; it does not install tools or change global PATH:

```powershell
.\codex\scripts\build.ps1 -LlvmMingwHome <portable-llvm-mingw-directory> -Test
.\codex\scripts\build.ps1 -LlvmMingwHome <portable-llvm-mingw-directory>

# MODEL_* / WORKER_LOCAL_TOKEN come from the environment (or a local loader you dot-source)
$env:MODEL_DEFAULT_MODEL = 'deepseek-v4.1-flash'
$env:MODEL_BASE_URL = 'https://opencode.ai/zen/go/v1'
.\codex\target\debug\codex-native-worker.exe init `
  --state .local\codex-worker --executable <absolute-pinned-codex.exe> `
  --project <committed-git-root> --project-id my-project
.\codex\scripts\start.ps1 -State .local\codex-worker -Port 18732
```

`init` requires explicit `--model`/`--base-url` or their `MODEL_DEFAULT_MODEL`/`MODEL_BASE_URL` environment values. There is no silent provider fallback. `MODEL_API_KEY` and any configured `LLM_HEADER_*` values stay in the environment; generated TOML stores variable names only. For this endpoint the centrally configured `LLM_HEADER_x_opencode_session` supplies its required session header. The shell environment inherits core operating-system variables and explicitly excludes model keys, model headers and host credentials.

`serve` requires an owner token of at least 24 characters in `WORKER_LOCAL_TOKEN` (or the name selected by `--token-env`). Store credentials only through the repository's central environment tooling. Never put them in registry/profile/source files. The listener binds `127.0.0.1`; every request requires bearer authentication. `X-Worker-Local-Store` rejects a changed source identity. `Idempotency-Key` must equal a mutating request's `requestKey`.

An initialized state is immutable: `init` refuses an existing registry, profile or SQLite marker, so another project/model cannot silently replace bindings under the same source identity. A new installation uses a new state directory. Required model keys and all header-variable names declared in the generated profile must be configured before model dispatch; missing values produce `UNCONFIGURED` capability records and `MODEL_CONFIGURATION_REQUIRED`. Historical metrics always report the task's frozen model.

The registered source project is read only. A task clones its committed baseline into its own owned workspace; uncommitted source changes are reported by preflight and are not copied. Codex gets a separate per-task `CODEX_HOME`. `profileId: MANAGED` and `loadsUserExtensions:false` identify this host's isolated generated home.

The adapter opts out of private reasoning and raw item-output/token deltas that the host does not project, and filters their legacy `codex/event/` notification equivalents before the bounded control queue. Completed-item facts, approval requests and `command/exec/outputDelta` terminal streams remain intact. This prevents an ordinary source-file read from crowding out control events without increasing the queue or exposing private output. Protocol failures retain a fixed known reason code; untrusted diagnostic text is not promoted to task reasons.

Newline-framed JSON-RPC stays bounded per direction. Inbound app-server lines accept up to 8 MiB — a single tool result can carry a whole repository file, and a real task once died `UNKNOWN`/`PROTOCOL_FRAME_LIMIT` when a ~500KB file pushed one line past the former 1 MiB bound. The host's own outbound writes stay bounded at 1 MiB: oversized `send()` payloads refuse `PROTOCOL_FRAME_LIMIT` before any bytes are written, never a silent truncation.

An explicit stopped-session follow-up also accepts proved FAILED/interrupted turns: matching durable turn seal, owned STOP proof, quiescence, no live peer and all existing effect/question/version/capacity gates are required. A new ownership transaction records the current boot together with generation/segment/epoch; it does not replay the old command or settle unknown effects. Strict PAUSE/RESUME remains unavailable. The Windows real-phone full-chain retest is **pending**; current cross-repository handoff is EnterpriseDevopsAI `docs/tasks/RMT-001/verification/20261029/authorization-native-continuation.md`. Historical macOS qualification below is unchanged.

## macOS arm64 build and bounded tool profile

On macOS **27.0.1 (26A434), arm64**, Rust **1.99.1** built and tested this host with the same locked crates. Use an existing Rust toolchain and native C compiler; the scripts do not install tools or change the global Codex installation. Release builds avoid slow debug hashing of the large pinned executable.

```sh
workers/codex/scripts/build.sh --release
workers/codex/scripts/build.sh --test
# MODEL_DEFAULT_MODEL / MODEL_BASE_URL / MODEL_API_KEY and any LLM_HEADER_*
# values are injected through the caller's approved environment loader.
workers/codex/target/release/codex-native-worker init \
  --state /absolute/owned/codex-state --executable /absolute/pinned/codex \
  --project /absolute/committed/git-root --project-id my-project \
  --tool-profile macos-in-process-v1
workers/codex/scripts/start.sh /absolute/owned/codex-state --port 18732
```

`--tool-profile macos-in-process-v1` is an explicit, versioned binding. The default `native` profile preserves the existing tools and is conservative about unproven writers. Both keep `profileId: MANAGED`; `identity.nativeToolProfile` exposes the selected local tool binding. This is not the separate Swift Worker profile or a general filesystem/network isolation guarantee.

The in-process profile disables shell tools, shell snapshots, apps and multi-agent use. A generated, non-secret `model-catalog.json` selects the pinned server's supported `ModelInfo.apply_patch_tool_type=freeform` and `shell_type=disabled` fields, retaining the exact configured model slug and provider. The catalog has its own digest, checked on startup and dispatch along with the executable and launch configuration. Changed bytes refuse with `ENGINE_CONFIG_CHANGED`. Native `fileChange` approval scope derives paths only from a previously observed `item/started` with the same item, thread, turn and generation; missing or stale evidence supplies no path authorization. The host never automatically approves.

The macOS wrapper executes `/usr/bin/sandbox-exec` with exactly `(version 1) (allow default) (deny process-fork)` before entering the pinned engine. This adds a process-fork restriction to the existing OS permissions; file and network access are not granted by this profile. Missing sandbox support refuses rather than falling back. Actual `fork` and `posix_spawn` denial, native `apply_patch`, STOP and stopped-session reopen were tested. Arbitrary shell/build commands are unavailable in this profile; a build can be a separate, explicitly bounded consumer operation.

A guardian in a separate owned process group monitors a pipe from the host and installs Darwin `kqueue NOTE_FORK` before the stopped wrapper continues into the engine. Host death, including SIGKILL or death before registration, closes the pipe and kills only that owned group. STOP first stops the engine root, drains the monitor, kills/reaps the managed root and guardian, and waits for the group to disappear. A fork is permanent in-memory taint, including after its marker is deleted. A monitor/setup failure cannot produce a seal. The ordinary native profile can still run commands, but any observed fork makes STOP **UNKNOWN**, `quiescent:false`, with no new artifact seal or stopped-session reopen. A process that escapes with `setsid` can survive group cleanup; the adversarial test proves this and cleans up its own exact fixture PID. Remote effects remain unproven. After a host crash, process cleanup does not establish a turn outcome: recovery stays UNKNOWN and never replays the prompt.

Mac clone and checkout use the same guardian/gated-exec/pipe lease with fixed local Git arguments, system/global Git configuration disabled and hooks excluded. Preparation needs Git's subprocesses, so it does not use the engine's fork-denial rule. Completion closes the lease and waits for the owned process group to disappear; it is a managed-group proof, not proof about arbitrary escaped processes. STOP waits for preparation to drain and checks the fresh preparation state before marking quiescence. A preparation timeout or cleanup failure remains unproven. A crash during preparation recovers UNKNOWN without clone replay or artifact publication.

## macOS command/build/test Runner profile

`--tool-profile macos-runner-v1` adds `run_command`, `run_build` and `run_tests` to the unchanged pinned app-server. It preserves native `apply_patch`, the model process fork denial, isolated `CODEX_HOME`, and wire `profileId: MANAGED`. Native shell, shell snapshots, apps and multi-agent tools stay disabled. The original `native` and file-only `macos-in-process-v1` modes remain available; an existing state never silently changes mode.

```sh
workers/codex/target/release/codex-native-worker init \
  --state /absolute/owned/codex-runner-state --executable /absolute/pinned/codex \
  --project /absolute/committed/git-root --project-id my-project \
  --tool-profile macos-runner-v1 \
  --command-runner /absolute/repository/workers/command-runner/main.mjs
workers/codex/scripts/start.sh /absolute/owned/codex-runner-state --port 0
```

The Runner uses Node **>=24.16, <25**. `init --runner-node ABS` (or `NWF_COMMAND_RUNNER_NODE`) selects it explicitly; otherwise `init` resolves `node` once. The physical executable and its digest persist in the immutable registry. The Runner entry point can also use `NWF_COMMAND_RUNNER_MAIN`. All sibling runtime `*.mjs` files are frozen by sorted filename and bytes, including the independent guardian. Startup and every dynamic dispatch recheck these bindings. Changing the Node environment variable at `serve` does not switch the frozen executable. A modified Runner source returns `RUNNER_CONFIG_CHANGED`.

The existing default schema pin remains unchanged. The same binary's `generate-json-schema --experimental` yields the separately pinned `af491b61…d1be` schema, which exposes `ThreadStartParams.dynamicTools`. Only this explicit profile initializes `experimentalApi:true`. Real `thread/start` registration, `item/tool/call` and result consumption were exercised; [macos-runner-profile.json](protocol/macos-runner-profile.json) records the exact seam. The configured model slug remains `deepseek-v4.1-flash`.

Each task owns an independent loopback Runner process and SQLite state under `runners/<task>`. A random bearer token stays in memory/environment; it never reaches the model or project. The host holds the Runner's stdin owner lease. Host SIGKILL closes that pipe; the Runner closes intake, kills its registered groups and preserves interrupted commands as UNKNOWN. The Runner inherits operating-system/build-tool paths and validated environment names only, excluding model/host credentials and shell injection variables. Command HOME/TMP/cache are private to their immutable Runner context.

Every callback must match a previously observed native dynamic item with the same task, generation, thread, turn, call ID, tool and arguments. The host derives the context and original request key; models cannot supply them. Each turn gets a new immutable context binding, including the command guard and engine digest. The SQLite request enters DISPATCHING before the single command POST. Lost replies cause only original-key GET lookups. The actual stdout/stderr, exitCode, timeout/cancellation and scoped stop proof persist in the original receipt; failed tests remain FAILED. The model receives bounded output (128 KiB per stream, explicitly marked when truncated), while the durable receipt retains the Runner's larger bounded output. A native `item/completed` cannot by itself settle a Runner effect. A crash recovers the request/effect as UNKNOWN without redispatching it.

STOP closes host admission durably, serializes with callback setup/dispatch, closes **all** task contexts, reconciles their commands by original keys, then stops the no-fork model process. Quiescence requires both proofs. Normal build-tool forks can finish successfully. `stopProof.scope` is `MODEL_NO_FORK_AND_REGISTERED_COMMAND_GROUPS`; `commandRunner.scope` is `REGISTERED_PROCESS_GROUP`. Arbitrary escaped processes and remote effects remain **NOT_PROVEN**. This is a trusted development profile, not arbitrary-code containment. Unknown Runner effects prevent new artifact sealing and stopped-session reopen.

## Implemented surface

`/local/v1` includes identity, engines/projects, preflights, task create/original-key lookup, detail, public messages/output, persisted event polling, usage, method-scoped input requests/responses, native follow-up/steer, STOP and sealed artifact downloads. Existing Business/PAC consumers can select this backend without rewriting references from another store.

Task detail reports only recorded timing: `runStartedAt` is the earliest durable turn fact (`turn.bound` dispatch or `turn.started` observation) and stays absent for a task that never dispatched a turn; `endedAt`/`completedAt` appear only on terminal states, copied from the fact that observed the settle — the frozen turn seal's `sealedAt`, the budget's `exceededAt`, the `binding.unavailable` event or the stop's applied observation. Nothing is synthesized from `createdAt` or wall-clock now.

Task detail and create preflight also carry a `sourceCapabilities` projection (`source-capabilities/1`): per-action source facts under `actions.<name>` with `state`/`reasonCode`/`limits`/`semantics`, computed per read and never cached. Action names use the dotted grammar the PAC `mobileControls` projection and the Pi host share — `sideQuestion.create`, `collaboration.create`, `collaboration.preflight`, `childMessages.read`, `adoption.preview`, `adoption.apply`, `handoff.export`, `handoff.seal`, `materials.upload`, `policy.presets`, `stop.affectedChildren` — so a PAC `actionCapability` lookup resolves them instead of reporting NOT_INTEGRATED. Rows with no PAC/Pi analogue keep honest source-local names (`messageSend`, `stop`, `transitions`) and the strict-PAUSE gap stays `pause`/`resume` = `UNSUPPORTED` (`NATIVE_BOUNDARY_GATE_ABSENT`). A sealed source reports every write-family action `BLOCKED_BY_STATE` (`SOURCE_SEALED`/`SOURCE_ALREADY_SEALED`) while reads stay `AVAILABLE`; unconfigured policy presets report `NOT_INTEGRATED` rather than a fabricated capability.

`/worker-host/v1` (also `/worker/v1`) exposes manifest, capability records and read-only `/operations/lookup`. Lookup uses `{requestKey, taskId?}` and never dispatches or requires a new idempotency key. Additional unimplemented design routes return an explicit route/action error and are absent from the manifest.

Native final messages are projected once by native item ID. Reasoning and raw tool diagnostics are excluded. Events retain durable decimal-string sequences and compatible `cursor/kind/occurredAt` fields. Cost remains unknown; usage has native-thread provenance. Native request IDs, native method, turn/thread and original command guards are preserved. Command/file approvals support the existing single-decision input shape. A single non-secret native user-input question can use a text response; unsupported forms fail explicitly.

SQLite uses WAL, synchronous FULL, foreign keys, a single process lock and atomic task/request acceptance. Same original key/body returns its receipt; changed body or guard conflicts. A dispatch/reply-loss window becomes **UNKNOWN after restart**, with no prompt replay. A provably never-dispatched ACCEPTED intent is sealed REJECTED. Source/store identity persists and boot identity changes. Future database versions are refused. Unknown writers keep the admission slot closed.

STOP is accepted with durable task/generation/command guards before native IDs exist. It closes intake, drains owned preparation, interrupts the original turn when known, terminates the managed tree and records its proof. Windows uses a kill-on-close Job Object, assigned before initialization, and checks its active process count reaches zero. Remote service effects are explicitly **not proven** by local process exit. A process from a previous boot is never treated as stopped merely because its native peer is missing.

A completed turn remains follow-up-capable but `quiescent:false`. A new task waits for STOP proof, maintaining one admitted task. Artifact publication requires that proof. Actual changed bytes and their manifest commit atomically in SQLite; downloads use opaque `file-<sha256>` IDs, verify hashes, enforce workspace ownership, exclude symlinks/oversized files and withhold known secret material. Published snapshots are immutable.

## W4a: budgets, scope, environment, audit and slots

Task creation accepts the W4a contract fields (`budget`, `writeScope`, `environment`); each is validated before the intent is admitted and the bound values persist in the task record. Store schema is `user_version=3`: v2 stores gain `turn_seals.reason`, `usage_ledger` and `budgets` in place; older stores still migrate through v2 first.

**Budgets are SOFT only.** Token usage arrives post-hoc through `thread/tokenUsage/updated`, so a cap cannot preempt a model request. Every update writes one `usage_ledger` row and accumulates decimal-string counters on the task (`usageTotals`) and the `budgets` row; native cumulative totals that reset on thread resume contribute only their positive delta. When a configured cap (`maxTotalTokens`/`maxInputTokens`/`maxOutputTokens`/`maxCostMicroUsd`) is crossed, one atomic transaction marks the budget row exceeded, sets `BUDGET_EXCEEDED` and emits `budget.exceeded` with the actual counters — once, not per subsequent update. The active turn is interrupted at its real boundary and sealed with `reason=BUDGET_EXCEEDED`; owned writers are stopped like STOP. Follow-up intake stays refused until a guarded `EXTEND_BUDGET` command supplies strictly larger caps: admission is the same single transaction as a reopen (fresh generation/segment/epoch) plus the budget replacement, `caps` may only grow past observed usage (`BUDGET_STILL_EXCEEDED`), and extension resumes on a new segment rather than mutating the sealed one. There is no arbitrary decrease or cap removal. Cost enforcement is only as real as provider-reported cost; missing cost stays `UNKNOWN`, never zero.

**Write scope** binds `extraWriteDirs` (existing absolute directories, canonicalized) and `denyPaths` (workspace-relative prefixes) at creation. Extra roots ride the native `turn/start` `sandboxPolicy` `{type:"workspaceWrite", writableRoots:[workspace, ...extra]}` so out-of-root writes are denied by the app-server itself. Deny paths inside the workspace are **host-observed, not preemptive**: every reported `fileChange` path is checked at item completion and a `git diff`/untracked sweep runs at each turn boundary; violations emit durable `write.scope.violation` facts (`OUT_OF_SCOPE`, `DENIED_PATH`, plus `NATIVE_*_REJECTED` when the engine itself refused) and a bounded `writeScopeViolations` projection. The recorded enforcement is `APP_SERVER_WRITABLE_ROOTS+HOST_OBSERVED_DENYLIST` — see `protocol/write-scope-gap.json` for what remains gap.

**Environment binding** is checked at launch admission, before any peer spawns: every `requiresCommands` entry must resolve through `where.exe` on Windows or `which` on macOS, every `requiresDirs` entry must exist and be readable. A miss terminates the task `BINDING_UNAVAILABLE` with a durable event and no fallback to the ambient environment. `envAllowlist` is not silently ignored: only validated `UPPER_SNAKE` names pass, any name containing `KEY`/`TOKEN`/`SECRET`/`PASSWORD` or starting `LLM_`/`MODEL_`/`WORKER_`/`ACS_`/`PAC_` is refused (`ENV_ALLOWLIST_DENIED`, invalid shapes `INVALID_ENV_NAME`), and admitted names are forwarded only into the managed app-server process environment — the host never reads or persists their values. The pinned app-server has no `shell_environment_policy` `include`/`set` knob we can use safely (`include` is rejected by strict config, `set` would persist ambient values to disk), so propagation from the managed process into tool-invoked shells is not claimed; see `protocol/environment-binding-gap.json`.

**Audit and diagnostics** are durable projections, not memory. `GET /worker-host/v1/tasks/{id}/audit` (`worker-audit/1`) folds `requests`, `events`, `usage_ledger`, `budgets`, `turn_seals`, `native_effects` and `artifact_manifests` into one ordered `items[]` (observed `at`, then sequence) covering request subjects/keys, intents and receipt phases, dispatch marks, native thread/turn ids, effect transitions, manifest writes and state transitions — prompt bodies are never projected. `GET .../diagnostics?redact=content` (`worker-diagnostics/1`) replays the task's durable events with body-bearing fields replaced by `{sha256,size}` references, environment-secret values redacted, and absolute paths outside the task workspace hashed instead of emitted.

**Concurrency slots** cap live tasks at `NWF_CODEX_MAX_ACTIVE_TASKS` (default `4`, parsed once at serve start; `0` or an invalid value refuses startup). Creation beyond the cap still admits durably as `launchState:"QUEUED"` with a monotonic `queueOrdinal`; task detail reports `queuePosition`. `drain_queue` — at startup, on terminal transitions, on binding failure and on budget shutdown — admits the FIFO head through `admit_queued`, one atomic mark from `QUEUED` to dispatching, then spawns launch. A queued intent was provably never dispatched: `recover()` leaves an ACCEPTED create receipt queued for re-evaluation instead of rejecting it, while a receipt that entered the dispatch window keeps the standard UNKNOWN outcome — never a double dispatch.

`tests/w4a.mjs` exercises the slice against the real pinned server and model: soft-cap exceed plus guarded `EXTEND_BUDGET`, `BINDING_UNAVAILABLE` with no peer spawn, write-scope violation facts, and FIFO slot release.

## W4b: terminals, MCP servers, skills and hooks

Task creation additionally accepts `mcpServers`, `skills` and `hooks`; each is validated before the intent is admitted, unexpected fields are refused, and the bound descriptors persist on the task. Store schema is `user_version=4`: v3 stores gain the durable `terminals` table in place. Evidence for every claim below is recorded in `protocol/w4b-evidence.json`; `protocol/adapter-schemas.json` carries the pinned schema fragments this slice consumes.

**Terminal sessions** (`POST /local/v1/tasks/{id}/terminals`, `/{tid}/input`, `/{tid}/output?cursor=`, `/{tid}/signal`, `DELETE`) ride the pinned `command/exec` family — the worker never spawns its own children. `argv` is a bounded non-empty list of bounded NUL-free strings; the session `cwd` is always the task workspace. `tty:true` is forwarded to the native ConPTY flag (real escape-byte output verified); anything else reports `pty:false` honestly. Stdout/stderr arrive over `command/exec/outputDelta` into a bounded 128 KiB transient ring: `output` returns `dataBase64`, `cursor`, `nextCursor` and honest `truncated`/`ringCapped` flags — never a replay of dropped bytes. `input` writes raw bytes through `command/exec/write` (no implicit newline). `signal` supports only `terminate` via `command/exec/terminate` — no POSIX vocabulary is claimed. The deferred `command/exec` response is the session's real exit fact: rows settle `EXITED` with the native code, `TERMINATED` when a managed STOP/budget job-kill was verified, or `LOST` when the transport died on its own (`NATIVE_PROCESS_EXITED`, `HOST_RESTART`, `TRANSPORT_GONE`). STOP proves the kill — the Windows kill-on-close job is drained to zero active processes — and `stopProof.terminals` names every session that was open; a racing exit settle still lands the same `TERMINATED`/`STOP_JOB_TERMINATED` fact. Up to `TERMINAL_MAX_PER_TASK=8` concurrent sessions; terminals hold no task-concurrency slot. `command/exec/resize` exists in the pin but is deliberately not exposed.

**MCP servers** bind through the task-scoped managed `CODEX_HOME`: each `{id,command,args,env?}` descriptor becomes a `[mcp_servers.<id>]` stdio table — no remote/URL servers, no OAuth. `env` names follow the same credential-shaped rejection as `envAllowlist` (`ENV_ALLOWLIST_DENIED`), and values are screened for secret material (`MCP_ENV_SECRET_VALUE`); `MODEL_API_KEY`/`LLM_HEADER_*`/`WORKER_*` are never propagated — the real-model verification shows the bound marker reaching the server while the model key is absent. After thread start/resume the host calls `config/mcpServer/reload` + `mcpServerStatus/list` and records `mcp.bound` (server, runtimeStatus, tool catalog) or `mcp.bind.failed` per server. Tool calls appear as `tool.*` durable facts with `type=mcpToolCall`; the pin routes call approval through `mcpServer/elicitation/request` (`_meta.codex_approval_kind="mcp_tool_call"`), which surfaces as an ordinary durable input request — the worker answer maps accept/decline/cancel onto the pinned `{action}` shape. A genuine structured-form elicitation is never auto-accepted: it declines honestly or is recorded `input.unsupported`. `_meta.tool_params` carriers are stripped from stored/projected params.

**Skills and hooks** stage into the same managed home. `skills:[{name,sourcePath}]` requires an absolute directory containing `SKILL.md`; files are copied into the task's CODEX_HOME skills root with per-file SHA-256 facts (`skill.bound`/`skill.bind.failed`), verified through `skills/list` at user scope plus `skills/extraRoots/set` for additional roots and `skills/changed` notifications. `hooks:[{event,command,timeoutSec?}]` validates against the pinned hook-event vocabulary, writes the managed `[hooks]`/`[features]` tables, and is trusted offline so `hooks/list` reports `trustStatus=trusted` — command hooks provably ran in the task workspace during verification with model credentials scrubbed from their environment; `hook.started`/`hook.completed` native notifications become durable events. A configured-but-unobserved hook is never claimed executed, and no generic third-party plugin/extension surface is claimed (absent on this pin).

`tests/w4b.mjs` exercises the slice end-to-end (22 checks): intake refusals; capability records; a real model MCP tool call with env binding and credential isolation; sha256 skill facts; trusted hooks that ran without the model key; piped and ConPTY terminals with stdin, cursor continuity, signal, delete; the STOP job-kill heartbeat proof; `HOST_RESTART` LOST recovery; and audit/diagnostics redaction.

## W5a: context packages, auxiliary sessions and transitions

Store schema is `user_version=5`: v4 stores gain `context_packages`, `context_package_sources`, `aux_sessions` and `transitions` in place. Evidence for every claim below is recorded in `protocol/w5a-evidence.json`.

**Frozen context packages** (`POST /local/v1/tasks/{id}/context-packages`, `GET` list + detail) copy source bytes at creation into the durable store — a later rewrite of the same workspace file cannot change a package's bytes or its sha256 digest (verified end-to-end). Sources are `{kind:"file",path}` (must resolve inside the task workspace by the existing lexical + realpath checks AND pass the writeScope denyPaths prefix rule; otherwise `PACKAGE_SOURCE_OUT_OF_SCOPE`, missing/non-file `PACKAGE_SOURCE_UNAVAILABLE`), `{kind:"text",text}` or `{kind:"summary",text}`. Bounds: 20 sources, 256 KiB per source, 64 KiB per text source, 1 MiB per package, 32 packages per task. `POST` is idempotent (`context-package.created` once); `GET detail` re-verifies every recorded sha256 and returns `digestVerified` + `coverage:"FROZEN_AT_CREATION"` — file sources carry base64 `content`, text/summary carry `text`. Packages are immutable — there is no update surface.

**Auxiliary sessions** (`POST .../auxiliary-sessions`, `GET` list/detail, `/{aid}/stop`, `/{aid}/deliver`) run a single bounded read-only turn on a **separate managed peer** with its own `CODEX_HOME` (task MCP servers, skills and hooks are deliberately not replicated) and an **isolated workspace snapshot** copied under `<state>/auxiliary/` (`.git` and symlinks skipped; bounded 4096 files / 32 MiB). `sandbox="read-only"` is requested honestly as a protocol-level hint — isolation is proven by the copy, not claimed as OS enforcement. Aux writes can never touch the main workspace. Named `contextPackageIds` are inlined into the aux instruction from their frozen durable bytes — the real-model verification answered a question whose marker existed only inside the package. Each session is an independent usage ledger: an optional `budget.maxTotalTokens` is SOFT/post-hoc exactly like the parent rule — a crossed cap interrupts a running session or settles `FAILED` with reasonCode `BUDGET_EXCEEDED` at the turn's accounting boundary, and aux usage never touches the parent budget. Up to 4 sessions per task (`AUX_SESSION_LIMIT`) plus a host-wide live cap `NWF_CODEX_MAX_ACTIVE_AUX` (`AUX_SESSION_BUSY`); a durable 10-minute deadline sweeps overdue sessions to `CANCELLED`/`AUX_DEADLINE`. `stop` kills only the aux peer. `deliver` is the only path that moves an answer into the main session: it uses the same follow-up/`turn/start` admission (live peer) or stopped-session reopen, stamps `deliveredAt` + `deliverRequestKey` atomically (the row stays `SUCCEEDED`; `aux-session.delivered` + `turn.bound` facts) and refuses a second delivery (`AUX_ALREADY_DELIVERED`) or an unfinished session (`AUX_NOT_FINISHED`). On host restart or HOST_CLOSE in-flight sessions reconcile `CANCELLED` (`HOST_RESTART_JOB_CLOSED`/`HOST_CLOSE`) — no continuation is claimed; terminal rows survive untouched.

**Assignment transitions** (`POST /local/v1/tasks/{id}/transitions`, `GET` list) support **same-engine/same-thread only**: the compatibility gate (`transition_compat`) refuses a different `engineId`, a different `model`, or any `toolAllowlist` change with `INCOMPATIBLE_TRANSITION` (409) before anything mutates — verified that state and the transitions table stay untouched. A compatible request quiesces the current owner through the **existing STOP machinery** (turn interrupt, job-kill drain, terminal settlement), and drains exactly the children a real STOP drains — aux sessions settle `CANCELLED`/`TRANSITION_QUIESCE`, running collaboration children `CANCELLED`/`PARENT_TRANSITION`, pending dependents `BLOCKED` — with the whole inventory recorded as `affectedChildren` on the `transition.quiesced` event, the durable transition row's compatibility object and the task's `transitionedFrom` fact. It emits `transition.quiesced`, then admits a new owner epoch in one atomic transaction: fresh generation/segment, `ownerEpoch+1`, durable transition row, `transition.admitted`, `launchState:"RESTORING"`. The peer reopens the **same native thread** via `thread/resume` (returned thread id must equal the stored `nativeSessionId`) plus `turn/start` with the original instruction or an explicit `instruction` continuation. Stale owners remain fenced by generation/session/turn/command/ownerEpoch bindings (`NATIVE_TARGET_CHANGED` verified); the durable transition row stores the full compatibility object under a `tr-` id, and `transition.quiesced` honestly names the quiesce proof — `MANAGED_STOP_QUIESCE` for a live owner (the pin has no boundary pause) or `COMPLETED_SESSION` for an already-sealed one. **Cross-engine migration is not implemented and is advertised as an explicit GAP capability** (`execution.crossEngineTransition`); same-thread model changes are equally refused.

`tests/w5a.mjs` exercises the slice end-to-end (38 checks): package freeze/scope/digest/limits/idempotency; real-model aux Q&A on inlined frozen context, snapshot isolation, stop, the 4-session cap, independent SOFT budget (`BUDGET_EXCEEDED` verified) and one-shot delivery on the same thread; live-task transition quiesce and same-thread reopen with epoch/generation/segment rotation, stale fencing and incompatible refusals; restart durability including `CANCELLED` aux reconciliation.

## W5b: writable collaborations and guarded adoption

Store schema is `user_version=6`: v5 stores gain `collaborations` and `collab_children` in place. Evidence for every claim below is recorded in `protocol/w5b-evidence.json`; parity checks N19/N20 are enabled and pass on the codex engine.

**Writable collaboration DAGs** (`POST /local/v1/tasks/{id}/collaborations`, `GET` list/detail, `/{cid}/stop`) launch up to 8 bounded writable children as a `dependsOn` DAG. Intake is atomic — request row, collaboration row, child rows and both acceptance events commit in one transaction — and validates dependency cycles (`COLLABORATION_DEPENDENCY_CYCLE`), unknown edges (`COLLABORATION_DEPENDENCY_UNKNOWN`), childId shape/uniqueness, goal length (≤8192), name length and context-package references before any row exists. Each child runs on a **separate managed peer with its own `CODEX_HOME`** (task MCP/skills/hooks not replicated) bound to an **isolated writable checkout** under `<state>/collab/{collaborationId}/{childId}/workspace` — a copy of the parent workspace (`.git` skipped) plus a recorded baseline manifest. A durable pump launches a child only when every dependency is `SUCCEEDED` (observed `after.startedAt >= writer.finishedAt`), marks dependents `BLOCKED` with `failedDeps` when a dependency fails, bounds live children by `NWF_CODEX_MAX_ACTIVE_COLLAB_CHILDREN` (default 4, host-wide) and seals the collaboration `COMPLETED`/`FAILED`/`CANCELLED` when all children are terminal. On Windows the pinned sandbox cannot auto-approve commands under `approvalPolicy="never"` — every exec is refused blocked-by-policy — so children run `on-request` and the **host answers each approval itself**: a command is granted only when its declared cwd is inside the child's checkout, a file change only when every reported path passes the child write scope; out-of-scope approvals decline with a durable `collaboration.child.scope_violation` fact and questions refuse outright. Child output, usage and tool calls are durable on the child row only — nothing enters the parent record, and child writes never touch the parent workspace directly (isolation is proven by the checkout copy, `COPY_ISOLATION_NOT_OS_READONLY`). `stop` marks pending children `BLOCKED`, peer-kills running ones to `CANCELLED`, and seals `CANCELLED`; a host restart reconciles RUNNING children `CANCELLED`/`HOST_RESTART_JOB_CLOSED`, pending `BLOCKED`, collaboration `CANCELLED` — verified end-to-end by killing the host mid-turn.

**Guarded explicit adoption** (`POST .../collaborations/{cid}/adoptions {requestKey,childId,mode:"ALL"|"FILES",paths?}`) is the only path child output reaches the parent. On child success its checkout diff vs the spawn baseline becomes the durable candidate set; only `SUCCEEDED` children adopt (`COLLABORATION_CHILD_NOT_FINISHED`). `FILES` requires every path to be a candidate (`ADOPTION_PATH_NOT_CANDIDATE`); `../`/absolute/non-normalized paths refuse `INVALID_ADOPTION_PATHS`. Parent drift under an adopted path conflicts as a `409 CONFLICT` with per-file material and **zero writes** — verified end-to-end: the drifted parent file survived untouched. Candidate bytes are preloaded and sha256-verified before the first parent write and all guards re-run immediately before writes (double-guard TOCTOU close). Repeat adoption of identical content is `NO_CHANGES`; the same `requestKey` replays the stored result. Every attempt is durable on the child row (`adoptions[]`) with `collaboration.adopted`/`collaboration.adoption.conflict` events; the audit projection carries hashes and counts, never contents.

`tests/w5b.mjs` exercises the slice end-to-end (25 checks): capabilities; every intake refusal; idempotent create/replay/conflict; a real-model writer+dependent DAG with ordering, isolated-checkout proof and no parent leak; adoption `ADOPTED`/replay/`NO_CHANGES`/path refusals/drift `409` zero-write; collaboration `stop` drain; and kill-restart honesty (`CANCELLED`/`BLOCKED`/`HOST_RESTART_JOB_CLOSED`). `worker-testkit/parity/launch.mjs codex` reports `PASS_SUBSET` including N19 `COLLABORATION_DAG_ISOLATED` and N20 `ADOPTION_EXPLICIT_GUARDED`.
